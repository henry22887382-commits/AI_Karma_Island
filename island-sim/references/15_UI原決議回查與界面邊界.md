## 3｜必須遵守的 UI 與世界資料邊界【現行規格交叉參照】

1. **時間顯示與模型輸入分開**：玩家觀察 UI 可讀取 72T／日、48T 白天／24T 夜晚、行動排序／晝夜；島民本身依第14章，收到自然語言時段提示而不顯示數字世界時鐘。不能把 UI 的全知資訊塞給模型。
2. **移動途中不屬於 Node**：不可把其移動前、移動中的旁人事件當成島民目擊。UI 可顯示移動流程，但具體動畫、座標插值、圖示樣式未見原始定案。
3. **只有 Node 的實際結算與現況產生報幕**；UI 的玩家歷史可查全島客觀事件，但 AI 看見什麼仍受 Node 範圍與該輪結算約束。
4. **公開訊息**是自然世界事件、不是私人聊天面板或鎖定的正式對話模式；不自動把其他 Node 的訊息交給島民。
5. **戰鬥不切換成獨立遊戲模式**：仍是 Node 中的事件與 72T 等待排程；不要因 UI 呈現需求新增傳統 RPG 戰鬥關卡狀態。
6. **安全區只由點燃營火產生**，中央營地實際配置營火，不是營地名稱自帶安全效果。
7. 玩家可查看死後傳記和客觀世界歷史；NPC/AI 島民沒有理由自動得到玩家的全知檢視資料。
8. 玩家 UI 裡的「人物編號」與 Node 編號要清楚區分；人物可能是 `3.2`，地圖 Node 是 `25`。

## 5｜供實作引用的已回收最低介面契約（不是新設計）

- 顯示當前世界和已結算事件的**唯讀**投影；不得將 UI 控件直接接成島民合法動作指令。
- 主島地圖、目前 Node 資訊、居民觀察、事件歷史、死亡傳記與運行控制，均須有可訪問的 UI 入口；**目前不規範入口排布**。
- 動態資料來源以世界引擎的正式結算及客觀資料庫為準，不能從 AI `intent` 推造事件。
- 遊戲內的對話應依新版公開非同步短訊顯示；過時的「正式對話握手」只能留在歷史作廢章節。
- 先保留先前 UI 討論沒有回收到的範圍，待原始聊天／圖稿真的可取得時再補；不得自行重造並覆蓋過去決議。
