# 09｜工程骨架、模型 Router、資料與介面

> 本章工程選型部分依收案時的實作方向整理，與玩法硬規則的證據級別不同。**以能維持既有世界規則、持久性與觀察價值為目標**；不因這份筆記隨意增減功能。

## 分層

| 層 | 責任 | 邊界 |
|---|---|---|
| 世界核心 | 72T時鐘、獨立等待、Node圖、NPC/敵人行為、事件抽取、戰鬥、HP與飽食、背包、裝備、死亡、掉落到期 | 只有核心能更動世界客觀狀態 |
| AI Router | 對每個活居民選定模型/版本，建立當前可見資訊，產生合法動作清單，發出呼叫、截取合法行動 | 模型不得直接寫資料庫或生成自認為已發生的物理結果 |
| 持久化 | 原子保存完整世界快照與追加式事件歷史、跨代次追蹤、隨機種子/抽取結果、死亡報告 | 個人對話上下文可於死後刪除；世界事實不可刪 |
| 內容表 | 地圖節點/邊、敵人參數、事件池、物品、文獻、掉落表、Boss機制 | 使用可版本管理的資料表；不要硬編成散落 Prompt 文字 |
| 觀察 UI | 節點幾何、居民棋子、資源、道具、戰鬥、公開短訊、碑文、世代及傳記 | 玩家不需要也不應直接代替 AI 執行動作 |

**目前收案方向**：本機 Node.js + TypeScript 引擎與前端、SQLite 儲存、線上多家模型 API 經 Router 接入。這組是收案時的實作基線；特別強制的是**功能與資料責任界線**，不在本文件憑空要求部署雲伺服器、微服務或換資料庫。

## 等待制的引擎資料（概念欄位，不硬綁命名）

- 單調遞增的 `world_time_T`（整數），`current_day` 及晝夜狀態。
- 每個參與行動實體的 `next_action_at`、目前 Node、角色/怪物速度、HP 等客觀狀態。
- 事件以 `at`, `actor`, `node`, `action`, `results`, `visible_to`, `random_draw` 等概念可重播；**不應把這些欄位的英文字串當使用者已要求的資料庫 schema 名稱**。
- 地面物件保留獨立生成時間/到期時間；採椰沙灘自然庫存是另類資源狀態，**不套 72T 過期**。
- 公開短訊應作可見世界事件入庫，指定目標下一次行動時能看到；其他觀察者依可見範圍閱讀，不使用鎖定聊天室。
- 勝利/怪物召喚/多擊/反擊/物品交付要**原子結算**，存檔或重試不可把 Boss 獎勵發兩次。
- 怪物的可行動時間也須加入同一排程系統；不要退回「怪物僅在玩家行動時免費反擊」的舊概念。

## AI 提示詞契約（舊稿的有效部分）

請按個人可見範圍輸入：

1. 上一次行動的客觀結果。
2. 目前個人 HP、飽食、睡眠資源、裝備、背包、位置。
3. 當前 Node 視野、他人可見操作、怪物/物件/公開短訊（不可給他人背包或內心獨白）。
4. 當前**合法**動作選項（從系統列出的白名單實例化，不是模型編造）。
5. 機器可解析的動作回覆格式。

模型的自由文字不具修改世界權限；不告訴模型『你是商人』『你一定要去地牢』『你應該悲傷』。允許截斷較舊當世記憶，而不是把人格鎖成固定角色卡。

## Q1–Q43 最新 AI 文字介面（以第14章為準）

**【定案】** 中文 Node 事件報幕＋當前唯一 JSON 快照＋中文結尾；每次現況全量替換舊 JSON；只提供引擎實例化的合法動作 ID；模型回傳唯一 JSON（`action_id`、30字內 `intent`、自由文字動作50字內 `text`）。不提供遊戲教學，不做獨立 `combat` 狀態。**本章前述「AI 提示詞契約（舊稿的有效部分）」僅是原理摘要，完整欄位與可見範圍應遵循 [14_AI決策提示詞與Node報幕.md](14_AI決策提示詞與Node報幕.md)**。

## 多模型與費用

- 最低目標模型規模 **8B**；不是一律 32B，也可有角色扮演專門模型。每位居民須分配已完成設定的模型卡；同一張卡可供多位居民共用，模型卡數量不固定。
- 每位活居民在**一生之內保持主要模型與採樣設定穩定**；新世代可分派新模型。
- 運行在使用者自己的電腦，使用網路 API；維持模型替代/備援能力。
- 使用目標每月 **US$10–20**，其中 **US$20** 為硬上限；紀錄 prompt、output、重試、訊息、死後傳記 API 成本，逼近上限降低呼叫頻率，達上限停止或暫停付費呼叫。
- 歷史候選十模型與 2026-10-19 原始報價參考另存 **12_舊稿保存.md**。**不把舊價格當成現價**。
- 2026-10-19 計價範例 `10×24=240決策/日` 已作廢；新的 72T 等待制須以實際執行日誌重新統計，**不能簡單做 240×3**（大動作占3T、每人排程不同）。
- 早期建議在接大模型前先用**不調 API 的隨機 Bot**做事件頻率與壽命分佈驗收，這是測試方法不是遊戲固定「30天壽命」。

## 觀察 UI（不是需要 AI 自己使用的遊戲操作面板）

- Node 圖連線、所處島民、時刻/晝夜、資源與道具容器。
- 點選居民可看代次、模型、個人 HP、狀態、背包、上一行動結果、可見資訊（這是玩家觀看權限，不代表其他島民可讀）。
- 公開短訊作為環境事件展示；按 Node/居民時間線回顧。
- 戰鬥事件、掉落、屍體、碑文、死後文學傳記及人物生命歷程。
- 暫停、續播、調速；不強塞動畫細節和裝飾系統。

**UI 原決議回查：**已在 [15_UI原決議回查與界面邊界.md](15_UI原決議回查與界面邊界.md) 增補證據分級的恢復結果：原稿確認的功能與主島原圖可用；具體版面、美術風格、滑鼠互動和控制器位置尚未取回原對話，不應由工程師憑空當作定案。

## 實作優先順序

1. 純核心排程、世界時間、Node、居民及持久化。
2. 生存、背包、裝備、掉落/過期、採集。
3. 九普通怪、Boss、多人戰鬥、召喚/雙擊/反傷、勝利資格。
4. 地表及三層事件池、唯一裝備、文字物件。
5. AI Router 和公開非同步短訊/交易。
6. 觀察 UI、人物傳記、長期模擬調校。

進入實作前**先填回原圖與早期掉落表資料**，不等同需要再發明新玩法。
