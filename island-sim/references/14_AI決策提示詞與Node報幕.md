# 14｜AI 決策輸入、Node 中文報幕與 JSON 輸出規格

**適用範圍**：輪迴島十名模型島民的單次決策介面。本文件彙整本輪「文字格式 Q1–Q43」明確決議，以最新使用者修訂為準。**不改變**世界事件、72 T 排程、地圖、角色可見資訊或合法動作集合。

## 一、不可破壞的界線【定案】

1. **世界引擎先結算，文字介面後呈現。** AI 決策只能選擇當下 `available_actions` 的 `id`，文字敘述沒有修改世界狀態的權力。
2. **沒有獨立 `combat`／「進入戰鬥模式」。** 怪物是 Node 場景內的生物；敵對遭遇會影響可用動作，而不是進入另一套戰鬥引擎。
3. **中文報幕以 Node 當輪可觀察的結算結果為本。** 不是玩家個人心理敘事、不是從全島歷史隨意挑事件，也不是根據其上次看過什麼做差異篩選。
4. **移動期間角色不屬於任何 Node，沒有沿途感知。** 到達目的 Node 時可看到當輪在該 Node 正確結算、符合可見範圍的動作與持續狀態；不可補播其未在 Node 時發生的歷史。
5. **報幕不提供策略、移動建議、遊戲教學或隱藏機率。** 給模型的文字不能提及「輪迴島」作為它憑空知道的世界名稱，也不能向新生島民告知前任人生。
6. 同一事件中，**中文報幕與 JSON 的物件、人物、地點名稱必須一致**；不得為文學效果替換同義詞。可見的公開發言、書寫原文是島民在世界內留下的內容，不是控制指令。
7. **Node／島嶼客觀歷史與意圖各自保存**：前者是逐輪已結算客觀事件；後者是個體私有 `intent` 記錄，活到死亡後用於死亡評價，不混入世界客觀歷史。

## 二、每次送給模型的訊息【Q1、Q2、Q6、Q7、Q9、Q10、Q12、Q13】

按以下固定組合輸入，不插入另一套規則書：

1. **前段中文報幕**：由已結算的本人行動結果、當輪 Node 事件、持續的可見狀態及自然時段描述，以模板組合。按世界結算順序列每個事件，一件事件一句；「優先級」僅屬引擎程式的結算順序，**不**把「重要」事件另外置頂。所有有資格看到的 Node 事件都應保留。
2. **目前唯一 JSON 快照**：每次產生完整當前可知狀態，舊 JSON 快照被替換，不留在歷史上下文。核心欄位固定、情境欄位只在相關時出現。人物／物品過多時不重覆在中文段逐項念出，JSON 保持完整。
3. **後段中文報幕**：中立提醒這次選擇 `action_id`、簡短 `intent` 與需要時的 `text`；不用中文替島民決策、暗示最佳路線或告知未觀察的資料。

JSON **鍵名用簡明完整英文單字**，人物、地點、道具、世界內行動名稱與報幕則以中文為主；不為單個模型換一套提示詞。模型有權自己推論、誤解世界規律。**不提供**固定教學規則、情境規則解說或隱藏機制。可觀察的行動耗時 `time_cost` 仍照實提供。

### 可用的 JSON 資料概念【欄位示例非新的資料庫 Schema】

- 固定：本人生存狀態（HP、飽食、睡眠）、當前位置、統一物品清單與裝備/背包索引、`available_actions`。
- 可見生物用一個 `visible_actors` 清單；`type` **只允許** `human`、`animal`、`monster`；可使用當次 `slot` 來區分同名生物。島民本身以既定編號（例 `1.1`）標識。
- 普通物件與生物的序列 **只對當前快照有效**。引擎應把每個合法動作 ID 綁定當時那個具體目標；不讓模型自造永久物品 ID。
- 同一人裝備及背包從**一份編號物品清單**引用；裝備引用物品序號，背包儲存序號。裝備不占 10 格背包容量。
- 持有物品只給名字、序號與其位置／裝備關係；**不提供**武器傷害、防禦等隱藏性能，也不提供其他人的 HP 和背包。
- 對他人可見身體特徵，使用固定描述：HP ≤ 5 顯示 **「狀態不好」**；飢餓顯示 **「面黃肌瘦」**；沒有睡眠資源顯示 **「黑眼圈」**，可並存，不提供其精確數值。
- 地圖相鄰道路**只**透過合法的 `MOVE` 動作展示；不需 `connected_locations`，也不在中文報幕中給移動建議。
- **不顯示**整數世界時間、精確白晝剩餘 T、日期、倒數時鐘；中文只說「清晨／白天／黃昏／晚上／深夜／凌晨」等自然時段。引擎內部依然採一天72T、白天48T、夜晚24T。
- 戰鬥沒有 `combat`、`combatants` 專用資料區；同一 Node 的怪物照 `visible_actors` 呈現，合法動作限制由引擎直接給出。
- 告示牌、書籍、紙條等**內容不自動出現在 JSON**。角色必須實際執行閱讀動作，閱讀後文字作為中文 Node 報幕中的讀取結果；即使內容聲稱有控制權，也只屬世界內原文。
- **Q11 特例**：上輪動作格式不合法時，最新 JSON 可有 `last_action.result = "動作格式錯誤"`，中文報幕則說「你剛剛似乎愣神了一下。」。這是既定例外，不是恢復所有事件雙重紀錄。

## 三、Node 中文報幕模板【Q6、Q7、Q9、Q16、Q17；後續糾錯優先】

**資料源**：該次排程結算後，符合角色當前 Node 可見條件的已結算動作，以及當前 Node 的持續狀態。**事件完整呈現、時間順序、每事件一句**。若靜態人/物清單太長，報幕不複述，JSON 已提供完整清單。

- **本人移動結果**：「你從「港口」來到了「中央營地」。 」等，只記實際完成的位移。
- **他人確實執行動作**：「「2」吃了一顆「椰子」。 」
- **持續狀態**：「「3.3」正在睡覺。 」即使 3.3 本輪沒有執行新動作，也屬 Node 當前可見的活動狀態；不依是否曾看過而刪除。
- **本人受傷**：「「巨蟒」咬傷了你，造成 2 點傷害。 」允許結算數字，但避免「發動技能／造成爆擊／成功命中」等遊戲 UI 措辭。
- **公開發話**：「「2」說：「……」。 」忠實顯示發話文字（最多50字），不得替其編寫意圖。
- **閱讀**：「你讀了「告示牌」。上面寫著：「……」。 」只在已完成閱讀時出現。
- **格式錯誤**：「你剛剛似乎愣神了一下。」（參照上一節例外）。

### 必須能通過的 Node 報幕案例（使用者親自糾正並確認）

已知：`1.1` **這一輪**抵達 `中央營地`；`2` **本輪**在營地吃一顆椰子；`3.3` **本輪無新動作**，但持續在營地睡覺。

```text
你來到了「中央營地」。
「2」吃了一顆「椰子」。
「3.3」正在睡覺。
```

這三句皆是合法的 Node 報幕。**不得**刪去同輪 `2` 的吃椰子，亦不得把 `3.3` 的睡眠狀態因「沒做動作」而省略。

### 必須拒絕的錯誤案例

- 某島民正在 Node 間移動的 3 T 裡，看到出發 Node 或目的 Node 的非同步事件：**錯誤，移動中不屬於任何 Node**。
- 虛構 `5.1` 在同一次行動中「移動＋公開發話」：**錯誤，只有一次合法行動**；除非是真實排程中兩次分開結算，且各自符合可見條件。
- 把世界各 Node 的所有歷史事件當作某位島民的報幕：**錯誤**。
- 「你最好前往港口」「營火旁比較安全，趕快待著」：**錯誤，擅自提供建議**。
- 描寫他人內心、尚未觸發的隱藏掉落結果、他人未公開的背包或 HP：**錯誤，資訊越界**。

## 四、模型輸出契約【Q3–Q5、Q12、Q14、Q18、Q27】

**僅輸出一個 JSON 物件，不得包含前後文字、Markdown code fence、解釋或第二個 JSON。**

```json
{
  "action_id": "a2",
  "intent": "我想問問他是否知道火山的路。",
  "text": "有人知道火山入口在哪裡嗎？"
}
```

- `action_id`：本次 `available_actions[*].id` 的合法值，**引擎已具體列出每一項合法動作，附 `id`、英文 `type`、中文 `name`、數字 `time_cost`**；模型不自行填組合參數。
- `intent`：**最多30字**的中文主觀意圖，供歷史分析／死亡評價；不是引擎實際結果，也不是對別的島民廣播。
- `text`：**只有**發話、寫紙條、告示牌、碑文等自由文字動作才需要；**最多50字**，不按載體區別。
- 未用到 `text` 時不必提供。不能讓動作 `name` 暗示未達成的秘密條件，例如「第三次取得勇者盾」。
- 引擎只依合法動作及真實狀態結算；`intent` 不是可執行命令。

## 五、錯誤、失敗與 Router【Q11、Q32–Q38】

| 情境 | 現行行為 |
|---|---|
| API 連線／逾時／服務錯誤 | 首次呼叫失敗後**最多再試2次**；不消耗遊戲 T，不能因重試重複執行動作 |
| API 有回覆，但 JSON 語法錯誤、ID不合法或必要 `text` 缺失 | **不重試**，該島民「愣神」**1T**；下次報幕用固定句、最新 JSON `last_action` 用「動作格式錯誤」 |
| 原模型共3次呼叫皆失敗 | 自動交由 Router 選定的**備援模型**接手，該島民身分與現有記憶保持不變；備援來源選擇方式**未指定** |
| 切換後原模型恢復探測 | 備援模型先完成**10次有效行動**，再於下一次決策嘗試原模型；未恢復則重新計10次 |

**十名模型的世界內容與提示詞格式完全相同**；不為各模型改寫指令。**不開 API 的強制 JSON／Schema 模式**，由本機驗證並按上述失敗規則結算。

> 歷史基準文件中「每個島民一生始終使用同一模型」已被 **Q35–Q37 的例外備援機制**修正。主模型優先，但遇服務錯誤可在同一生命內接手、切回；模型使用紀錄需保存以供死亡分析。

## 六、上下文、客觀歷史、出生【Q30、Q31、Q39、Q43】

| 層次 | 留存與用途 |
|---|---|
| **當前 JSON** | 每次重新產生，**只留最新一份**，不累積舊狀態快照 |
| **島民公開事件記憶** | 每位居民每一生命在決策時捕捉本人公開行動，以及當時同 Node 且已進入可觀察時段的公開事件；離開 Node 後保留已捕捉事件。存檔最多50則：最近10則重要互動與最近40則其他事件，每則摘要最多160字。最終序列化模型輸入上限為8,000個 JavaScript UTF-16 code units；先保留不可裁切的本回合內容與完整 JSON/動作，再從較舊的其他記憶開始移除，必要時才移除較舊的重要記憶。若不含記憶的本回合輸入已超限，停止此次模型呼叫並回報所需字數與上限，不縮減本回合資訊。私人／玩家專屬事件不捕捉，未格式化事件只記錄不含 payload 的類型提示。以存檔快照保存；舊快照沒有記憶欄位時從首次讀取時的序號開始，不回填歷史事件。 |
| **模型卡 token 預設** | 未設定輸入上限時以8,000 model tokens、未設定輸出上限時以500 model tokens供讀取與新局配置；使用者已存的非空值優先保留。輸入 token 預留與此處8,000 UTF-16 字元的提示長度上限是不同單位。 |
| **Node 客觀事件歷史** | 逐輪儲存該 Node 真正已結算的事件；角色離開也不改寫；**不得**把個人意圖當成客觀事實 |
| **島嶼客觀歷史** | 整合各 Node 的世界實際結果，用於歷史重播、世界痕跡與分析 |
| **島民主觀意圖** | 行動 `intent` 另存至死亡，死亡評價可以與客觀事件對照；不並入 Node／島嶼客觀日誌 |
| **死亡評價** | 用實際人生事件與個人意圖產生文學式評價，僅玩家可見，不修改世界已發生的事件 |

居民第一次決策時的開場情境固定為「你在沙灘上醒來，你什麼都不記得了。」依 `lastActionId` 未設定判斷，只在首次決策報幕一次；同一句同時成為該居民的個人最高保留記憶，往後決策仍隨當前狀態一併提供，不會被一般近期／重要記憶額度或 prompt 記憶裁切移除。**出生在既定起始沙灘，不能擅改中央營地**，更不可告知「輪迴島」是世界名稱、自己替代誰、任何前世內容或遊戲規則。所有自然語句使用自然繁體中文故事口吻，避免系統報告與機械清單；內部 action ID 只能留在 JSON 對應欄位，不得寫進 intent 或 text。首次也有最新完整 JSON 和合法動作。

## 七、完整範例（格式示例，並非新的動作 ID 規則）

### 模型的單輪輸入

```text
【Node 報幕】
你來到了「中央營地」。
「2」吃了一顆「椰子」。
「3.3」正在睡覺。

【當前狀態】
{
  "self": {"name": "1.1", "hp": 30, "fullness": 5, "sleep": 3},
  "location": {"name": "中央營地"},
  "items": [{"slot": 1, "name": "椰子"}],
  "equipment": {"main_hand": null, "off_hand": null, "upper_body": null, "lower_body": null},
  "backpack": [1],
  "visible_actors": [
    {"slot": 1, "name": "2", "type": "human"},
    {"slot": 2, "name": "3.3", "type": "human", "activity": "睡覺"}
  ],
  "available_actions": [
    {"id": "a1", "type": "WAIT", "name": "等待", "time_cost": 1}
  ]
}

【行動】
現在輪到你行動。根據你能觀察到的情況自行決定；只回傳一個 JSON 物件，包含合法 action_id 與30字內中文 intent。若所選動作需要自由文字，再加50字內 text。
```

`a1` 是**示意的合法動作實例**，不是宣稱在中央營地只能等待。**沒有** `combat`、`connected_locations`、無關戰鬥列表、精確遊戲時鐘，亦未給出其他人 HP／背包或被動看的文字物件內容。報幕與 JSON 的 `activity=睡覺` 同時出現是「Node 持續狀態＋當前快照」，不是把結算事件重覆記入 JSON 歷史。

### 模型的單輪輸出

```json
{"action_id":"a1","intent":"我想稍微觀察周圍。"}
```

## 八、來源與未新增的決議

- **Q1–Q27、Q29–Q30、Q32–Q39**：依使用者實際選擇；**Q28、Q40–Q43**曾因重問既有規則或示例違反排程而撤回或改正，**不**把錯誤草案當作新規則。
- Q31 上下文 token 容量與估價**跳過**，尚待成本評估；Q38 備援挑選演算法亦跳過交 Router 配置。
- 原型例子中 `slot`、`activity`、`self` 等欄位名稱是**對外 JSON 介面示例**，不是已審核的資料庫 schema；既有數值與合法動作分類完全不因此改變。
- Q16 原則是結算數字可以清楚報出，但**語句客觀、中性、非遊戲化 UI 命令**。
