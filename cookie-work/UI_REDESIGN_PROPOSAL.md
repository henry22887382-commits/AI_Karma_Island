# 輪迴島介面重設建議書

## 目的與設計原則

本文件整理各頁的功能去重、操作直覺、遊戲體驗與版面建議，供後續介面改動使用。可依使用者體驗自由新增、合併、重排或移除頁面，也可改變目前的導覽與技術架構；前提是原有功能與資料可達性不流失，並以實際遊戲流程驗收。

產品經理角度：讓玩家容易開始、觀察、理解角色與回到重要資料。
工程角度：讓資料來源、保存範圍、操作結果與錯誤狀態清楚，避免重複入口產生不同步。
專業遊戲介面角度：優先呈現遊戲世界、角色和可採取的行動，控制面板只在需要時出現，不以更多狀態標籤取代遊戲畫面。

建議遵循以下原則：

- **遊戲性優先：**玩家打開觀察介面時，先看到島嶼正在發生什麼，而不是工程狀態表。
- **場景優先：**Node 檢視應是一個圖像化、角色化、遊戲化的場景展示。玩家點選地圖上的 Node 後，看見該地點的場景與角色；不得把地圖變成狀態徽章、圖層和資訊標籤的堆疊面板。
- **漸進揭露：**常用資訊直接可見；角色詳情、地形／地點資料、告示和近期事件可由場景中的角色、物件、區域或清楚的詳情入口開啟。
- **單一來源、情境入口：**同一設定可從不同情境進入，但入口共用同一資料與回饋。只有作用真的不同時才分開。
- **玩家語言與工程語言分層：**遊戲內文字寫給玩家；原始錯誤、代碼與診斷資訊集中在診斷介面。
- **保留功能與響應式品質：**頁面重組不能讓功能消失、藏到無法找到，或只在桌面可用。

以下狀態來自最新程式覆核；尚未經瀏覽器視覺驗收：

- **Node 場景已落地。**目前工作由此基礎繼續，不再把場景檢視列為尚未實作的起始工作。
- **已完成程式修正：**居民選取後恢復鍵盤焦點；窄螢幕上的移動目的地保持可見並可換行；場景標頭使用最近場景時間。相關修改涉及 `observer.ts` 與 `observer.css`。這些程式改動尚未經瀏覽器視覺驗收。
- **開始頁配置已調整。**使用者圈選的居民模型分配與模型卡設定完整內容置於右側主工作區；左側保留導覽、死亡總結及地圖選擇。此版面尚未做瀏覽器視覺驗收。
- **Node 地圖配置維持原樣。**資料場景仍使用左側地圖 8 欄、右側資訊 4 欄配置，沒有改動地圖佈局；先前曾錯誤地暫移至地圖下方，該變更已撤回。

- **地圖儲存已移至地圖工作區。**先前「存檔按鈕仍在文本工作區側欄」是舊版程式檢查結果，不應當作目前仍存在的缺陷；後續仍要在實際瀏覽器確認入口可見、保存結果明確。
- **本輪已實作的其他調整：**居民名冊加入搜尋，刷新後保留查詢；Node 場景詳情改由父區域自然捲動，同時保留必要的地圖側欄與原始輸出捲動。涉及 `observer.ts`、`observer.css`、`server.ts`。**錯誤紀錄狀態：**靜態核對確認頂部 `renderControls` 只有模擬狀態、速度與操作，沒有資料同步或待處理詳情；同步狀態與待處理資訊原已集中在錯誤紀錄頁。本輪沒有移除頂部重複資料，保留錯誤紀錄頁作為唯一同步／待處理呈現處。
- 事件時間線仍為每頁 6 筆；篩選／可見性語意與意圖規則未改。
- 居民人數兩入口仍共用同一設定。

## Node 場景檢視方向

將「Node 可視化」定義為玩家點選 Node 後進入或展開的地點場景，而非在地圖上加更多狀態 UI。

- 使用既有地圖圖像、地形與地點資料構成場景；可加入角色化的居民、怪物、營火、告示或可互動物件呈現。只有有資料支持的內容才顯示，不虛構不存在的角色或事件。
- 用角色姿態、所在位置、場景物件和簡短敘事傳達地點狀態。場景的美術表現可逐步增強，不要求先替每個資料欄位造一個圖示。
- 點選角色可查看居民詳情；點選地點或場景物件可查看地形、正式地點名稱及告示。最近事件在場景旁或場景詳情內提供入口。
- 讓玩家容易返回全島地圖或切換相鄰 Node。所選 Node 和地圖位置保持清楚，避免迷失所在。
- 不堆疊狀態圖層、徽章、常駐圖例或工程資訊。若場景無法承載某些細節，透過單一詳情面板或次層檢視按需呈現。
- 保留既有詳情、居民、地形、告示和最近事件的可達性；可重新安排為場景互動、詳情面板或次頁，但需在驗收清單逐項確認。

Node 場景已落地，所列焦點回復、窄螢幕移動目的地可見性／換行及最近場景時間標頭修正已完成；以上仍是設計原則與持續驗收要求。可繼續調整地圖與側欄配置、場景呈現和互動，但不得省略既有資料或互動功能。

## 不應誤併的功能

- **生命傳記與死亡總結是不同資料。**前者是居民生命資料，後者是模型產生的死亡回顧；可放在同一歷史工作區下作為不同頁籤，但需明確標示來源與內容。
- **地圖上的近期五筆事件與歷史頁是預覽和完整歷史。**地圖可保留精簡近期事件入口；歷史頁保留完整、可篩選或分頁的紀錄，兩者作用不同。Node 場景歷史還需清楚表達事件發生時間與目前模擬時間的關係，避免把相對時間、排序或時間戳解讀錯誤。
- **地圖預覽與工房編輯 profile 選擇是不同任務。**預覽用來查看地圖呈現與內容；編輯選擇用來指定要修改、保存的 profile。可在編輯前提供預覽，但需清楚標示「預覽」或「編輯中」，不可讓瀏覽或選看誤觸發修改。
- **地圖預覽與開局選用也不同。**預覽是查看內容；開局選用會決定新局採用哪個 profile。保留地圖預覽的可達性，並在開始新局前確認所選地圖。
- **開局選地圖與工房編輯地圖 profile 不是重複操作。**開局選擇決定新局使用哪張地圖；工房選擇決定編輯或保存哪個 profile。兩者可連結，但畫面要分清「使用」與「編輯」。
- **居民模型卡分配與模型卡管理不是同一任務。**開局流程需要為居民選擇已設定的卡；連線和模型卡管理可置於設定區，不需重複堆疊在每位居民表單中。

## 頁面與導覽重組建議

頁面名稱與數量可自由調整。以下是功能分組，不要求沿用目前頁籤或路由：

1. **島嶼／世界：**以全島地圖及世界動態為中心；選取 Node 後進入圖像化場景。地圖保留位置導航，近期事件作為摘要入口。
2. **角色：**提供居民名單、搜尋／篩選、單人詳情和目前行動。居民名冊搜尋及刷新後保留查詢已實作；其他長清單可依需要採狀態篩選或分頁，避免狹窄的長按鈕清單。
3. **歷史：**提供完整事件時間線與生命傳記；保留死亡總結作為清楚分開的資料類型或獨立次頁。
4. **模型與遊戲設定：**集中模型卡管理、居民分配、死亡總結模型卡和相關指示。開局流程提供必要選擇，不重複另一套連線設定。
5. **工房：**按工作任務呈現文本編輯、地圖 profile 編輯與下一局居民人數。可重排為不同頁或工作區，不需被目前程式架構綁住。
6. **診斷：**集中格式錯誤、完整原始輸出與資料同步資訊。一般玩家頁只顯示易懂摘要和可採取的下一步。

### 開局準備

先讓玩家選擇「開始新局」或「載入存檔」，再依序處理居民數、居民模型卡分配、死亡總結設定和本局地圖。可用步驟式流程、單頁分區或其他直覺方式，不必維持目前版型。收合或離開時仍需看見已選內容摘要；新局設定要清楚說明不會修改正在進行的遊戲。

## 遊戲畫面、版面與操作

- 讓場景或主要工作內容佔據主要視覺空間；設定、清單和診斷按需展開，避免控制面板擠壓遊戲場景。
- 建立明確的視覺層級：頁面目的、目前選取對象、主要操作、次要資訊依重要性排列；相似操作使用一致的位置與命名。
- 提供清楚的選取、載入、保存、成功、失敗、空內容和未儲存狀態。錯誤訊息要說明原因及可行的下一步。
- 居民名冊已提供搜尋且刷新後保留查詢；模型分配清單和死亡總結列表可提供搜尋、篩選或分頁，不要靠縮小字體或塞進固定高度窗格解決。
- 文字清單、編輯器與預覽可依工作需要分欄；每個內層捲動區都要讓使用者知道自己正在捲動哪個區域。若多欄在窄畫面變得擁擠，改為明確切換面板。
- 保持常用操作可見且可鍵盤操作；滑鼠懸停不得是唯一提示方式。選取狀態要有文字、形狀或位置線索，不單靠顏色。
- 玩家可見文案優先寫角色正在做什麼、在哪裡、發生什麼結果。像 `move:18` 或 `surface:rock-exploration` 這類原始標記放在診斷資訊，不出現在一般敘事。
- 地點、地形與角色命名沿用遊戲內正式名稱；錯誤頁可保留錯誤碼並附上中文解釋。

## 響應式設計與視窗／捲動證據邊界

目前唯讀程式檢查確認：observer shell 的部分觀察介面採 `height: 100dvh` 與 `overflow: hidden`，部分面板自行捲動，世界面板亦有隱藏溢位設定；Node 場景詳情本輪改由父區域自然捲動，並保留必要的地圖側欄及原始輸出捲動。其他頁面和分頁則有允許頁面延伸的規則。工房文本清單與預覽採內層捲動，並有窄畫面工作區切換。模型卡分配與死亡總結等區域可能形成長清單，需提供搜尋、篩選、分頁或分批顯示。這些是程式結構和內容量的證據，不代表已確認實際畫面遭裁切或使用困難。

這些程式與截圖證據指出需要做跨頁一致性和易用性檢查，**尚不能單憑 CSS 或個別截圖認定內容已被裁切或形成實際缺陷**。目前未做瀏覽器視覺驗收；Node 場景與地圖存檔入口也尚未在瀏覽器確認實際視覺與操作結果。需在不同視窗尺寸執行真實操作和完整頁面巡查，不把截圖視窗寬度與 CSS breakpoint 的差異預先當成錯誤。

建議以使用者任務決定捲動方式，而非強制每頁只有一個捲動區：

- 桌面可在主要場景旁放詳情；平板減少並列欄位；手機改單欄或清楚的面板切換。
- 確保主要操作、保存回饋、目前選取對象和返回地圖的入口不會被固定視窗遮住。
- 地圖可有自己的移動與縮放操作；相鄰清單或詳情若需獨立捲動，需有清楚邊界並避免誤捲地圖。
- 長清單採搜尋、篩選、分頁或分批載入。文本預覽可獨立捲動，但在窄畫面提供清楚面板切換。
- 對 320px 手機到寬螢幕逐步檢查；以實際瀏覽器操作確認焦點、文字換行、清單可達性、地圖選點和捲動行為。

## 實作階段與驗收

### 階段 1：功能盤點與體驗架構

列出所有玩家任務、資料、入口與保存範圍；標記可合併的重複操作及不可合併的相鄰功能。以已落地的 Node 場景為基礎確認資訊架構，記錄尚待修正與驗收的互動。

**驗收：**居民、事件、生命傳記、死亡總結、模型卡、診斷、開局、存檔、地圖 profile、Node 地形／告示及文本編輯都有明確去處和返回路徑。

### 階段 2：核心場景與導覽

全島到 Node 場景流程及鍵盤焦點回復、窄螢幕移動目的地可見性／換行、最近場景時間標頭修正均已完成；本階段後續工作是重整主要導覽，同時維持玩家可專注於遊戲世界。

**驗收：**Node 檢視呈現場景而非狀態 UI 堆疊；角色、地形、告示和最近事件均可查閱；玩家能辨識目前位置與返回方式。

### 階段 3：工作流程與重複入口

確認居民人數兩入口共用資料與保存回饋；保留已移至地圖工作區的地圖保存入口並驗收其狀態；分清文本卡套用和整體保存，整理開局選擇及模型卡管理。

**驗收：**相同設定從不同入口修改後保持一致；每個保存操作明確告知保存對象、結果與失敗狀態；開局選圖與工房編輯 profile 不混淆。

### 階段 4：內容呈現、排版與響應式

調整玩家語言與工程診斷的分層、長清單工具、空狀態、主要視覺層級及窄畫面面板配置。

**驗收：**長清單可搜尋／篩選／分頁；玩家頁不露出未解釋的內部代碼；桌面、平板及手機主要任務均可完成，內容和控制可達。

### 階段 5：實際瀏覽器驗收

待使用者清空待驗收項目後，集中一次以真實瀏覽器操作全島地圖、Node 場景、角色詳情、近期事件與完整歷史、生命傳記、死亡總結、診斷、開局、存檔和工房功能。本輪尚未執行測試。

**驗收：**在寬窄視窗完成上述任務；檢查沒有被遮蔽的主要操作、無法到達的內容、迷失的捲動區或失去的原有功能。逐項記錄通過、修正或待驗證結果；未做 E2E 的項目不得標成已驗收。

## 目前證據與限制

尚未做瀏覽器視覺驗收。型別檢查目前失敗，輸出包含多處既有錯誤；本輪沒有執行測試，也不將型別錯誤歸因於本輪介面調整。

本建議依截圖與 `island-sim/src/ui/observer.ts`、`observer.css`、`server.ts`、`editor.ts` 等唯讀程式覆核整理。本輪程式修改包括開始頁將居民模型分配及模型卡設定完整內容置於右側主工作區、居民名冊搜尋且刷新保留查詢、Node 詳情父區域自然捲動並保留必要側欄／原始輸出捲動；Node 資料場景保持地圖 8 欄加右側 4 欄，未改地圖佈局，先前一次錯誤移至地圖下方的暫改已撤回；場景保留死亡居民過濾、怪物真實名稱、物件可讀名稱、最近事件和真實公開訊息對話泡泡。另有居民選取後焦點恢復、窄螢幕移動目的地可見並換行、場景標頭採最近場景時間等修正。靜態核對確認頂部 `renderControls` 只有模擬狀態／速度／操作，沒有資料同步或待處理詳情；同步狀態與待處理資訊原已集中於錯誤紀錄頁，本輪沒有移除頂部重複資料，保留 diagnostics 作為唯一呈現處。事件時間線仍每頁 6 筆，篩選／可見性語意與意圖規則未改。以上項目尚待使用者清空待驗收項目後一次測試；本輪沒有執行測試，亦未做瀏覽器視覺驗收。待確認的畫面問題是驗收項目，不是已證實缺陷。
